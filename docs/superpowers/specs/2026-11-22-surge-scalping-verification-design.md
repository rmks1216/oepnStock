- **목적**: "급등이 시작될 때 들어가 2~3% 먹고 나오는" 단타가 비용을 빼고도 이익이 나는지 키움 1분봉 실데이터로 검증한다.

## 1. 데이터

- **출처**: 키움 REST API 1분봉(`ka10080`, `upd_stkpc_tp=1` 수정주가). 조회만 하고 주문 기능은 만들지 않는다.
- **기간**: 2025-11-03 ~ 2026-11-20. 키움이 1분봉을 약 1년치만 준다(삼성전자로 확인).
- **시간대**: 정규장(09:00~15:30) 봉만 쓴다. 대체거래소(넥스트레이드) 시간대 봉은 버린다.
- **가격 부호**: 키움 분봉 가격에는 `-` 부호가 붙어 오므로 절댓값으로 바꾼다.

## 2. 검증할 매매 규칙

하루의 흐름은 다음 순서다.

```
아침: 감시 대상 30종목 확정 (2.1)
  → 장중: 1분봉마다 급등 신호 확인 (2.2)
  → 신호 다음 봉 시가에 매수 (2.3)
  → 익절·손절·강제 청산 중 먼저 오는 것으로 매도 (2.4)
  → 모든 손익에 비용 반영 (2.5)
```

### 2.1 감시 대상

- 거래일마다 **전일 거래대금 상위 30종목**(KOSPI+KOSDAQ, 코넥스 제외)을 그날 감시한다.
- 전일 거래대금은 KRX 일봉(pykrx `get_market_ohlcv_by_ticker`)에서 구한다.
- 그날 아침에 알 수 있는 정보만 쓰므로 미래 정보가 섞이지 않는다.

### 2.2 급등 시작 신호

1분봉 t 가 끝날 때 아래 두 조건을 **모두** 만족하면 신호로 본다.

1. **가격**: t 종가가 5분 전(t-5) 종가보다 3% 이상 높다.
2. **거래량**: t-4 ~ t 5개 봉의 거래량 합이, 그 직전 30개 봉(t-34 ~ t-5)의 1분 평균 거래량 × 5 의 5배 이상이다.

**신호를 받는 시간**

- 직전 30분 데이터가 필요하므로 첫 신호는 09:35 봉부터 가능하다.
- 신호는 15:00 봉까지만 받는다.

### 2.3 진입

- 신호가 난 봉의 **다음 봉 시가**에 산다. 사람이 신호를 보고 주문하는 지연을 반영한 것이다.
- 한 종목은 하루에 한 번만 들어간다.
- 동시 보유는 최대 3종목이다. 3종목을 들고 있을 때 난 신호는 건너뛰고, 건너뛴 횟수를 기록한다.
- 한 번 들어갈 때 자본의 1/3 을 쓴다. 수익을 재투자하지 않는다(거래마다 같은 금액).

### 2.4 청산

진입한 봉부터 매 봉의 고가·저가로 확인한다.

| 조건 | 체결 가격 |
|---|---|
| 고가가 진입가 +2.5% 이상 (익절) | 진입가 +2.5% |
| 저가가 진입가 -2% 이하 (손절) | 진입가 -2%. 봉 시가가 이미 그 아래면 시가 |
| 한 봉에서 둘 다 닿음 | 손절로 처리. 분봉으로는 어느 쪽이 먼저인지 알 수 없어 불리한 쪽으로 가정 |
| 15:19 봉까지 둘 다 안 닿음 (강제 청산) | 15:19 봉 종가. 15:20부터는 장 마감 동시호가라 그 전에 판다 |

### 2.5 비용

프로젝트 설정값(`oepnstock/config/settings.py` 의 `TradingCosts`)을 쓴다.

| 항목 | 비율 |
|---|---|
| 매수 수수료 | 0.015% |
| 매도 수수료 | 0.015% |
| 매도 세금 | 0.23% |
| 슬리피지 | 매수·매도 각 0.2% |
| **왕복 합계** | **약 0.66%** |

이 비용이면 비용을 뺀 한 번의 결과는 이기면 +1.84%, 지면 -2.66% 이다. 따라서 **본전 승률은 약 59%** 다.

## 3. 판정 기준

### 3.1 전제조건

거래가 **100회 이상**일 것. 못 채우면 판정하지 않고 불합격으로 본다.

### 3.2 합격 기준

아래를 **모두** 만족해야 합격이다.

| # | 기준 | 보려는 것 |
|---|---|---|
| 1 | 비용을 뺀 거래당 평균수익률이 0 보다 크다 | 이익이 나는가 |
| 2 | 그 평균의 95% 신뢰구간 하한이 0 보다 크다(부트스트랩 10,000회) | 우연과 구별되는가 |
| 3 | 12개 월 중 7개 월 이상에서 월별 수익 합계가 플러스다 | 한두 달의 큰 수익에 기대지 않는가 |

### 3.3 결과별 행동

| 결과 | 행동 |
|---|---|
| 합격 | 1년·상승장 한 번뿐이라는 한계가 있으므로 바로 실전에 쓰지 않는다. 모의투자 키를 받아 1~2개월 포워드 테스트를 한다 |
| 불합격 | 급등주 단타는 접고 체크리스트 도구 설계로 돌아간다 |

### 3.4 금지 규칙

- 결과를 본 뒤 조건 숫자(3%, 5배, +2.5%, -2% 등)를 고쳐 같은 기간으로 다시 돌리지 않는다.
- 결과를 본 뒤 이 판정 기준을 바꾸지 않는다.

### 3.5 해석상 한계

아래 내용은 리포트에 함께 적는다.

- 1년치, 그것도 KOSPI 가 크게 오른 해 하나뿐이다.
- 키움이 현재 상장 종목의 분봉만 준다면 상장폐지된 급등주가 빠진다. 받지 못한 종목 수를 리포트에 적는다.
- 분봉 안에서의 가격 순서를 모르므로 실제 체결과 다를 수 있다.

## 4. 구현 구조

새 패키지 `oepnstock/intraday/` 에 둔다. 기존 일봉 백테스터와 섞지 않는다.

| 파일 | 하는 일 | 의존 |
|---|---|---|
| `kiwoom_client.py` | 토큰 발급(만료 시각 `expires_dt` 전에 재발급), 분봉 연속조회, `data/cache/kiwoom/` 에 종목별 저장 | requests, `.env` |
| `universe.py` | 날짜별 전일 거래대금 상위 30종목 | `KRXDataProvider` |
| `surge_rules.py` | 신호 판정, 진입·청산 모의 계산. 네트워크 없이 데이터프레임만 받는다 | pandas |
| `scripts/verify_surge.py` | 수집 → 모의 계산 → 판정 → `reports/surge_verification_*.md` 저장 | 위 세 모듈 |

**`kiwoom_client.py` 주의사항**

- 키와 토큰을 로그에 남기지 않는다.
- 서버는 `KIWOOM_MOCK` 값으로 고른다. 다만 검증 스크립트는 조회만 하므로 실전 서버를 쓴다(지금 키가 실전용이다).

**수집량**

- 1년 동안 감시 대상에 한 번이라도 들어간 종목 전부의 분봉이 필요하다.
- 수백 종목이 될 수 있고 종목당 1~2분 걸린다.
- 캐시에 있으면 다시 받지 않는다.

## 6. 축소판: 신호 뒤 수익률 분포 (전체 검증보다 먼저 실행)

**추가일**: 2026-11-22. 결과를 보기 전에 적었다.

### 6.1 왜 먼저 하는가

이 규칙을 한국 분봉으로 직접 검증한 연구는 찾지 못했다. 다만 간접 근거는 대부분 불리하다.

- 개별 종목은 장중·단기에 되돌아가는 경향이 더 강하다.
- 미국 선물 5분봉 연구(arXiv 2605.04004)에서는 OHLCV만 쓰고 다음 봉 시가에 진입하는 신호 14종이 모두 비용을 넘지 못했다.

그래서 진입·청산 시뮬레이터를 만들기 전에, 신호 뒤 가격이 비용만큼이라도 오르는지부터 본다.

### 6.2 측정 방법

- **이벤트:** 2.1 감시 대상에서 2.2 신호가 난 경우다. 종목당 하루 첫 신호만 쓴다. 동시 보유 제한은 두지 않는다.
- **기준가:** 신호 다음 봉 시가(2.3과 같다).
- **비용을 빼기 전 수익률 두 가지**
  - **R30:** 진입 봉부터 30번째 봉의 종가. 15:19 봉을 넘으면 15:19 봉 종가.
  - **R종가:** 15:19 봉 종가.
- **참고값:** 2.4 익절·손절 규칙을 적용하고 2.5 비용을 뺀 순수익률과 승률. 판정에는 쓰지 않는다.
- **데이터:** 키움 `ka10080` 에 `base_dt`(기준일)를 넣어 종목·날짜마다 한 번 조회한다. 정규장 봉만 쓴다.

### 6.3 판정 기준

| 결과 | 행동 |
|---|---|
| 이벤트가 100회 미만 | 접는다 |
| R30 평균과 R종가 평균이 모두 0.66% 이하 | 접는다. 왕복 비용도 못 넘기 때문이다 |
| 둘 중 하나라도 0.66% 초과 | 1~5장의 전체 검증으로 간다 |

3.4 금지 규칙(결과를 본 뒤 숫자와 기준을 바꾸지 않는다)은 여기에도 똑같이 적용한다.
